river-virtual-keyboard-v1

window manager keyboard event injection

(index)

This protocol gives the river-window-management-v1 window manager a race-free way to send virtual keyboard events to the client with keyboard focus as part of a window management manage sequence.

The key words "must", "must not", "required", "shall", "shall not", "should", "should not", "recommended", "may", and "optional" in this document are to be interpreted as described in IETF RFC 2119.

river_virtual_keyboard_manager_v1

river virtual global interface

Interface
Version 1

This global interface should only be advertised to the client if the river_window_manager_v1 global is also advertised.

river_virtual_keyboard_manager_v1.destroy

destroy the river_virtual_keyboard_v1 object

Destructor Request
Since Version 1

This request indicates that the client will no longer use the river_virtual_keyboard_v1 object.

river_virtual_keyboard_manager_v1.sync_keyboard

sync a virtual keyboard with the manage sequence

Request
Since Version 1

Mark a zwp_virtual_keyboard_v1 as synchronized with the river_window_manager_v1 manage sequence.

Virtual keyboard events generated by the zwp_virtual_keyboard_v1.key and zwp_virtual_keyboard_v1.modifiers requests on the given virtual keyboard are queued and sent to the client with keyboard focus in a batch at the end of each manage sequence.

Note that the capacity of the compositor's event queue is necessarily finite, though the compositor should choose large enough limits to allow any "reasonable" usage of this protocol.

This request must be made before the first zwp_virtual_keyboard_v1.keymap request for the given virtual keyboard.

This request only has an effect if the client is the active river window manager.

This request is idempotent, subsequent requests for the same zwp_virtual_keyboard_v1 object have no effect.
